# 活動、待辦與抽卡規劃

Milestone 8 提供兩組完全離線、由使用者手動維護的日常規劃功能。它們只讀寫本機
SQLite，不讀取遊戲記憶體、log、帳號 API 或網路資料，也不會控制遊戲。

## 活動與待辦

- 待辦可設定類型、優先級、到期時間、關聯活動、備註、隱藏狀態，以及每日或每週的
  版本化 recurrence 規則。
- UI 以 `Asia/Taipei` 顯示與輸入時間；資料庫統一保存 UTC aware datetime。到期分類以
  使用者目前時間計算為逾期、今日、三日內、本週、未定日期或稍後。
- 延後時間會暫時取代原到期時間參與分類。已完成或隱藏項目不會進入 Dashboard 的
  未完成到期摘要。
- 完成重複待辦時，原 occurrence 會保留完成時間，並在同一 transaction 建立新的本機
  ID。即使舊畫面重複送出同一 ID，也不會重複建立下一筆。
- 晚於原定時間才完成時，下一筆會前進到第一個真正位於完成時間之後的 occurrence，
  不會一次建立多筆已錯過項目。
- 未知或未來版本的 recurrence JSON 會原樣保留並要求人工編輯；系統不會模糊猜成
  daily 或 weekly。
- 刪除活動時，資料庫外鍵會把關聯待辦的 `event_id` 設為 null，待辦本身與完成紀錄
  都會保留。

## 抽卡資源與目標

目前資源包含星聲、限定角色抽券、限定武器抽券、兩池墊抽與保證狀態。墊抽與保證會
保存供使用者查看，但 V1 不會以隱藏公式把它們換算成需求抽數。每個目標的最保守、一般、
樂觀需求都必須由使用者明確輸入；缺少或非法值保持 null，規劃結果會標示資料不足。

星聲換算固定為每抽 160。直接抽券保持角色／武器兩種資源，不會跨池混用；未知券種
不會被猜測。多目標依優先級、目標日期及穩定本機 ID 排序，先分配專用券，再使用共享
星聲，因此同一份資源不會被多個目標重複計算。

未來收入可以標記為：

- `general`：三種情境皆包含；
- `conservative`：最保守、一般與樂觀皆包含；
- `typical`：一般與樂觀包含；
- `optimistic`：只有樂觀情境包含。

收入必須有日期、日期未早於規劃基準日且尚未領取，才會在適用的目標截止日前納入。
已過期但未標記領取、無日期、超過截止日、已領取或含未知券種的收入會被排除或只採
可確認部分，並產生可見 warning；已過期目標也會明確標示。三張情境卡
顯示已配置到角色／武器目標的抽數、剩餘未分配星聲、總缺口與警告；它們不是抽卡機率
預測，也不代表官方保底規則。

## 資料與安全假設

- 所有資料以 active local dataset 隔離並使用短 transaction 保存，重新啟動後仍存在。
- 系統不抓取 Tier List、公告、活動或兌換碼；日後的版本化資料匯入必須是獨立且預設
  關閉的功能。
- UI、資料庫服務與領域規則分離；資料庫工作由單一背景 worker 執行，不阻塞 Qt UI。
- 這些頁面不啟動畫面擷取。只有使用者在聲骸強化頁明確按下開始後，monitor capture
  才可能運作。
