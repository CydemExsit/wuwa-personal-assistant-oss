# V1.0.5 聲骸選擇頁擷取修正

## 問題

V1.0.4 可以用頁首 ROI 以接近 100% 的信心辨識「聲骸選擇」頁，但內容 OCR 可能一直停在
「畫面切換中」。實機 metadata log 顯示頁面分類已成功，卻沒有任何 content OCR 被排程，
因此這不是顯示器選錯、MSS 擷取失敗或 RapidOCR 模型缺失。

原因是選擇頁的內容穩定門同時比較 23 個 ROI，其中包含 15 個可見卡片左上角。任何一張
卡片的動畫、徽章或清單變動都會把 0.6 秒計時器歸零。記憶體內 30-frame 診斷中，舊規則
只有 2／29 組相鄰樣本能讓全部 ROI 同時低於 Hamming 門檻，與使用者畫面完全一致。

## 修正

- 15 個卡片角落、棄置圖示與完整清單仍保留在 content packet，供裝備／棄置／身分證據解析；
  它們不再全部成為 OCR 的阻塞條件。
- 選擇頁穩定門比較右側名稱、等級、COST、主／副詞條及右下裝配文字。
- 為避免兩顆相同文字的聲骸被當成同一狀態，穩定 fingerprint 額外包含「唯一選中格」與
  「選中卡中央卡面 pHash」。兩者只是在同次擷取中使用的短期證據，不是遊戲唯一 ID。
- 清單 ROI 底部延伸至 `y=1300`，讓第 5 列三個選中框都完整落在記憶體裁切內。
- 棄置切換不使用容易抖動的原始 pHash；改由固定小 ROI 的保守紅色／中性圖示判斷產生
  離散 marker，並把同一證據交給 parser。圖示與 `已棄置` toast 衝突時仍輸出 `null`。
- 無法取得唯一金框時使用未知 sentinel，仍可讓文字 OCR 正常進行，不以缺少視覺證據猜值。
- Capture 紀錄的 ROI 設定版本升為 `2560x1440-zh-TW-v3`。

## 驗證

- 回歸測試證明 15 個卡片狀態區同時動畫不再阻塞 content OCR。
- 切換選中格或同一格的卡面圖樣仍會建立新的穩定狀態。
- 第 5 列 cell 13 → 14 及同一顆聲骸的棄置切換都會建立新狀態；未棄置／已棄置私有
  樣本分別保守辨識為 `false`／`true`。
- 使用私有第 2 張 2560x1440 截圖與本機 RapidOCR 走完整記憶體流程，約 0.61 秒即排程
  `echo_selection` OCR；所有 4 個 full-frame lease 均釋放，沒有寫出完整畫面。
- 使用已裝配於愛彌斯的私有正向樣本，刻意讓其餘 14 張卡片角落逐幀變動；新版仍在
  0.61 秒產生 `+25 / COST 4 / is_equipped=true`，整體信心為 0.8827。
- 原始私人截圖、ROI 像素與 OCR 文字未加入 Git 或診斷 log。

## 後續修正（2026-09-19）

選擇頁確認使用者已取消棄置標記時，同一個 Session 現在會從 `discarded_active` 回到
`active`，並將 `is_discarded=false` 保存到資料庫。先前僅處理標記為棄置的方向，取消後
仍會顯示舊狀態，且再次標記也不會產生新的棄置事件。

- 不明或互相衝突的辨識結果仍保留先前確認的狀態；已消耗聲骸不會被重新啟用。
- 歷史棄置事件保留，取消以新的 observation 與 Session 摘要記錄；再次棄置會產生新的
  `echo_marked_discarded` 事件，不需要變更事件格式或資料庫 schema。
- 回歸測試涵蓋取消、未知狀態、再次棄置、已消耗來源保護，以及關閉／重開資料庫後的
  狀態與歷史保存。
- 修正建置環境 PATH 混入其他工具 DLL 的問題：建置時隔離原生相依搜尋路徑，避免包入
  不相容的 ICU 而在匯入 `QtCore` 時中止；完成後還原呼叫端環境。
