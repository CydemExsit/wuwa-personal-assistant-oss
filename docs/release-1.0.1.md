# V1.0.1 可用性救援版

這個版本直接處理首次實際使用所暴露的問題，不把「測試通過」等同於「人能使用」。

## 已修正

- 移除 Qt 不支援的樣式選擇器；未勾選／已勾選／停用 checkbox 與 radio 都有明確邊框、底色與焦點狀態。
- 首次設定縮成三頁快速開始；角色、資料集、資料路徑與評分模板不再阻擋聲骸辨識。
- 顯示器使用左側／右側、Windows 顯示器編號、實體名稱、解析度與主要螢幕標示，不再只顯示無法辨識的 Monitor 1／2。
- 測試螢幕時會在記憶體內執行小範圍頁面分類；全黑或近乎無細節的擷取不再回報成功。完整 frame 會在 OCR 前釋放且不寫入硬碟。
- 即時穩定門只比較固定頁首與文字語意 ROI，不再讓星空背景、角色動畫、大面板或素材按鈕永遠重設計時器。
- 聲骸頁改成「尚未開始／正在辨識／已有結果」三種清楚狀態，直接顯示目前看到的頁型、confidence 與下一個遊戲內手動步驟。
- 新增只含 metadata 的 capture／OCR 日誌；不記錄完整畫面、OCR 原文、聲骸名稱、詞條、角色名稱或本機路徑。
- 空白 Dashboard 只顯示一個主要下一步，不再先展示一排沒有意義的零值卡片。
- 角色頁新增版本化本機目錄、搜尋與多選批次加入；目錄不代表帳號擁有、Tier 或卡池狀態。
- 活動與抽卡頁可顯示由使用者明確按鈕更新的庫洛官方繁中公開公告；個人資源、墊抽與保證狀態仍只保存在本機，不會由公告推導。

## 實機診斷結論

原版本確實曾建立六次 capture session，但沒有產生任何聲骸 observation，也沒有留下可用的 capture/OCR 記錄。MSS 與本機 RapidOCR 可辨識遊戲所在的 2560x1440 螢幕；主要故障是穩定門把持續動畫的 ROI 一起納入比較，使 OCR 長時間無法排程。修正後相同被動 monitor-only pipeline 能進入頁面 OCR，且所有 frame lease 都已釋放。

## 公開資料與已知限制

公告同步只在使用者按下更新按鈕時，向精確白名單中的庫洛官方 HTTPS JSON 發出 GET；啟動時只讀本機快取。活動日期若無法從文章正文唯一確認會保持 unknown，絕不把文章發布日或 2099 哨兵日期猜成活動期限。

角色目錄目前是隨版本封裝的公開名稱索引，不會讀取遊戲帳號或自動判斷持有角色。要安全取得帳號實際角色、星聲、保底或素材仍需手動輸入或未來由使用者明確匯入本機檔案；本工具不會藉由遊戲程序、封包、log 或帳號 API 取得這些資料。
