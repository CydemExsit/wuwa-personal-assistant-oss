# V1.0.7 自動裝備登記與辨識修正

## 操作結果

- 清楚讀到「角色名裝配中」時自動登記角色，不必先按「保留」。角色名中的分隔點與空白
  會統一比對，避免 `秧秧・玄翎` 與 `秧秧·玄翎` 分成兩個角色。
- 左側選中裝備圈與清單中選中聲骸的卡面唯一吻合時，自動填入角色的第 1–5 格。
  裝備圈本身不足以證明位置；重複卡面、遮擋、模糊畫面會保留為位置待確認。
- 只確定角色的聲骸會顯示於角色頁下方「已登記裝備」。新辨識不會覆蓋手動配裝；
  新的明確位置可替換先前自動配裝，原聲骸紀錄保留。明確卸下只解除自動配裝。
- 長名稱後的 `+25` 會分離為等級，也支援實測 `COST-3` 的 OCR 分隔符號。
- 從右下「合鳴效果」及套裝件數同列讀取套裝名稱，包含「雪落無聲之願」。
  名稱會顯示於即時結果、歷史和角色聲骸欄；切換強化頁後保留同一聲骸先前讀到的套裝。
- 辨識到遮擋右下區域的「剪取與繪圖／剪取工具」通知時，略過整筆結果，避免錯誤資料
  進入聲骸追蹤。裝備條與效果區的動畫不會被加入全域穩定等待條件。

## 既有資料

修復服務只接受已停止的指定辨識批次，先預覽，再於單一交易內重新檢查並套用。
長名稱、等級及 COST 需有原始 OCR 明確證據；使用者修改優先，原始 OCR 不改動。
套裝、位置缺少原始畫面證據時保持未知。重複角色僅在預設資料未編輯且無其他關聯時
封存；相似聲骸不會依詞條或數量合併。修復可重跑，欄位修改保留 audit。

使用者該批實際有 36 筆聲骸紀錄、41 次觀察、6 個角色身分。安全修復包括 3 筆長名稱
及等級、1 筆 COST，涉及 11 個歷史欄位；35 筆有強證據的所屬角色可補登。
另 1 筆角色名信心不足，保持待確認。6 筆相似紀錄缺乏足夠同物證據，原樣保留。
舊版沒有保存套裝與裝備位置區域，不能事後猜填。

所有 OCR 與修復在本機執行，實際資料修改前建立一致性 SQLite 備份；不操作遊戲，
不新增畫面上傳或完整畫面持久化。Windows 建置繼續隔離外部 DLL 搜尋路徑。

## 驗證

雪落無聲之願、緋雪與第 1 格；前一張截圖為愛彌斯第 3 格。合成測試覆盖全部 5 個位置、
不符卡面與重複卡面。GUI 整合測試涵蓋不按保留直接登記、未知位置顯示與手動選擇保護。

安全掃描通過。實際資料修復及 Windows 封裝驗證記錄在 `.codex/WORK_PROGRESS.md`。
Windows 封裝的離線 OCR 與隔離啟動測試通過，126 個封裝模組與來源碼一致，版本為 1.0.7，
未混入外部 ICU DLL。修復前備份保存於本機應用程式的 `backups` 目錄。
