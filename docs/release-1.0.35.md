# v1.0.35 — 辨識、評分與畫面效能

聲骸機率評分改用有上限的原生批次運算及分布快取；OCR 重用完全相同 ROI 的原始結果。配裝總覽保留未變動卡片，隱藏單件視圖延後建立；既有資料庫通過健康檢查後省略不必要的 migration 啟動。

本機基準中，+5 首次機率計算約 1,744 → 100 ms，重算約 1.27 ms；重複圖片的完整離線流程約 1,057 → 59 ms。50 位角色的相同資料更新約 266 → 0.14 ms，單一角色變更約 269 → 6.43 ms。完整範圍、資源觀測與限制見 [效能量測與架構](performance.md)。新畫面仍需要 OCR 推論，穩定等待保持 600 ms。

評分公式、機率、原始辨識信心值、人工確認規則與 SQLite 格式保持相容。28 組設定共 507 個 projection 案例、11 張私人圖片及三輪完整重播與 v1.0.34 相同；原始資料庫未改寫，副本的七個 service 輸出相同。Windows 125%／200% 畫面已驗證。

成品：`dist/releases/1.0.35/WuwaPersonalAssistant/WuwaPersonalAssistant.exe`。關閉舊版後啟動，保留同層 `_internal` 資料夾。

## 八項交付範圍

| 目標 | 實作與驗收 |
| --- | --- |
| 1. 效能基準 | 可重跑實體擷取／穩定判定、評分、辨識、UI、啟動與完整離線重播，區分首次／重複及測量範圍 |
| 2. 辨識速度 | 完全相同 ROI 重用；私人樣本與信心值一致、生命週期失效測試 |
| 3. 評分速度 | 有限批次精確計算、跨目標重用分布、507 案例及 CI 基準 fixture |
| 4. 畫面流暢 | 卡片差異更新與隱藏頁延後建立；Windows DPR 1.25／2.0 |
| 5. 資源 | 限制快取數量／容量、減少重建 widget；兩版各通過 15 分鐘 5 Hz 持續排程與五次啟停，frame 全數釋放 |
| 6. 架構品質 | 運算、OCR 快取、Qt reconciliation 分離；失效與關閉邊界明確；C++ 原型含轉換／封裝比較後選擇 NumPy |
| 7. 啟動與打包 | 目前 schema 健康快速路徑、延遲載入 Alembic、縮減額外 Qt 翻譯資料，保留本機 OCR 模型 |
| 8. 品質與交付 | 全套測試／靜態／依賴／安全檢查、Windows 啟動／離線 OCR／模組資源稽核、分支與 main CI |

本機完整品質門檻通過：1,454 項測試通過，1 項既有選用連線測試略過；另外新增並通過重新整理時捲動位置保持的回歸測試。Ruff、格式、mypy（186 個來源檔）、依賴、安全與差異檢查均通過。

15 分鐘持續運作比較中，每版保存 132 個結果，模型只載入一次，停止後沒有殘留 worker，Qt widget 數固定；輪流換圖階段平均 CPU 消耗減少約 73%。兩版同時執行，此比較限於程序資源；RSS 峰值約 430.42 → 424.55 MB，保留歷史仍會占用記憶體。

Windows 成品啟動與離線 OCR 自我測試通過，167 個應用模組、48 個資源與 125 個二進位檔稽核通過，包含新加入的三個效能模組。成品由 367.54 MB 縮至 358.39 MB，減少約 9.15 MB／2.5%；Qt hook 所需的基本翻譯與繁體中文仍保留。打包報告位於成品同層 `reports`；交付時另核對分支及最終 main CI。

成品既有空資料庫的程序啟動測量，兩版各 7 次，中位數 1,752 → 1,640 ms（約減少 6.4%）；範圍為不啟動擷取及 presenter 的 smoke startup。
