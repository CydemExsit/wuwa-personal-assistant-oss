# v1.0.13 — 修正清單辨識長時間等待

已能判斷「聲骸選擇」卻持續顯示「畫面切換中」的原因，是透明文字區後方的動畫不斷重設穩定計時。舊版逾時後再次確認頁型，卻沒有讀取聲骸內容；手動重新辨識也會回到同一循環。本機紀錄中可看到反覆成功的頁型辨識、沒有內容結果。

## 修正

- 文字穩定判斷保留可見的白色／金色字形，減少暗色背景動畫的影響；實際 OCR 仍使用原始 ROI，保留原始信心值。
- 已確認清單時直接重新讀取內容，內容辨識前仍重新檢查頁型，培養或其他頁面不保存聲骸資料。
- 文字區持續變動約兩秒時，只要選取格、卡片圖示、棄置狀態及角色位置已穩定，就開始恢復辨識。恢復路徑需要兩次獨立畫面的詞條、等級、套裝及裝備資訊一致，才提交紀錄。選取資訊變動、停止或重設會取消待確認結果。
- 「立即重新辨識」優先重讀新的畫面，仍保留短暫的選取穩定檢查及兩次內容確認。即使頁面標題背景持續抖動，也會定期重新分類，不再無限等待。
- 仍使用單一 OCR worker；恢復內容重試至少間隔一秒，頁型重試至少兩秒，不會同時建立多個辨識工作。介面會說明正在再次確認文字。

以上秒數為排程門檻；實際更新還包含本機 OCR 執行時間。若使用者持續切換選取，工具仍會等待選取穩定。

## 驗證與範圍

新增像素級動畫重現，涵蓋暗色及亮色背景、標題抖動、自動／手動恢復；另驗證選取格、圖示、棄置及位置變動不可跳過穩定檢查。真實 tracker 測試確認第一次結果不會寫入，兩次不一致會繼續確認，重設、停止及辨識中切換會丟棄舊結果。

使用先前提供的 +22 截圖，在記憶體中加入合成背景變動，再通過正式 ROI 排程與 RapidOCR：正常讀出名稱、四條副詞條與等級，恢復確認後仍只有一個工作階段。這是提供圖片的離線重播，並非新擷取的遊戲實況。私人圖片未寫入版本控制或上傳。

既有九張私人樣本、+17／+22、長名稱、套裝及角色位置辨識均另行回歸；評分方式與歷史資料沿用先前版本。

完整品質檢查通過：942 項測試成功、1 項既有的選用網路測試跳過，另通過 Ruff、型別、依賴及安全檢查。完整介面以提供圖片作為測試來源，完成開始、自動辨識、立即重新辨識、同一紀錄更新及停止；全部 53 個畫面記憶體租用均已釋放。1200×800 與 1440×900 畫面確認可見名稱、+22、四條副詞條及評分。使用隔離測試資料庫，沒有修改使用者的原始資料。
