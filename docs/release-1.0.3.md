# V1.0.3 裝備辨識與同批次回訪

V1.0.3 針對實際使用後發現的兩個問題進行修正：工具現在能保守判斷選中的聲骸是否已裝備，並能在同一次辨識中處理 A→B→A 的回訪，而不重複建立相同紀錄。

## 已裝備狀態

- 使用一張未加入 Git 的 2560×1440 繁體中文私有正向樣本校準。
- 選擇頁會交叉檢查唯一金色選中框、卡片左上角色肖像、右下「…裝配中」及「卸下／裝配」文字。
- 證據一致時輸出 `is_equipped=true` 或 `false`；證據缺失或互相矛盾時輸出 `null`，不猜測。
- 角色肖像只證明「有角色裝配此聲骸」。V1.0.3 不由肖像猜角色名稱，也不因左側金圈就自動寫入永久裝備槽位。

## OCR 信心與完整性

- 已知的 `+` 裝飾字元與 `X/x/十` 圖示前綴，在同列數值具有高信心時可做保守校準。
- 模糊詞彙、未知文字、低信心文字或低信心數值不會被強行提高 confidence。
- 選擇頁必須具備名稱、合法等級、COST 1／3／4、兩條主屬性，以及符合等級的完整副詞條數量，才可略過人工確認。
- 缺少必要欄位時維持「需要人工確認」，不以零值或猜測補齊。

## 同一次辨識中的 A→B→A

遊戲畫面沒有可安全使用的聲骸唯一 ID。工具只建立本次 Capture 期間有效的短期視覺證據：

- 唯一選中格與選中框座標；
- 排除角色徽章、選中外框與文字後的卡面 64-bit pHash；
- 同一個 3×5 可見清單中 15 格卡面脈絡的 64-bit pHash；
- 名稱、等級、COST、兩條主屬性與該等級全部副詞條的完整結構化簽名。

只有同一次 Capture 內存在唯一未消耗候選，而且格位、卡面、清單脈絡及完整結構化簽名全部吻合時，才會接回原本的本機 Session。合法回訪只新增回訪事件，不重複新增 observation 或評分；若裝備狀態、等級或詞條真的改變，才保存新的 observation。

證據不足、候選不唯一、雜湊不符、結構化欄位衝突，或來源 Session 已進入素材消耗流程時，一律不自動合併。持久化層也會再次驗證既有證據，不信任上游單方面宣稱「這是同一顆」。

只保存格位、選中框座標與不可還原畫面的短雜湊；不保存卡片裁切、完整 frame 或影片。這些證據不跨 Capture 使用，也不視為遊戲提供的唯一 ID。

## 資料相容性

- 不需要資料庫 migration。
- V1.0.2 及更早的既有歷史不會自動回填、合併或刪除。
- 新辨識規則只作用於升級至 V1.0.3 後建立的結果。

## 已知限制

- Live OCR 仍以 2560×1440、繁體中文介面為校準基準。
- 如果同一顆聲骸先在選擇頁出現、之後升級，再經過其他聲骸回訪，證據不足時可能保守地分成新紀錄；這是避免誤合併的安全取捨。
- `is_equipped=true` 不會自動關聯到本機角色或槽位；使用者仍可在辨識結果中選擇角色與位置後手動確認。
