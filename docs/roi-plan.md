# 2560x1440 頁面分類與 ROI 規劃

本 Proof of Concept 僅支援《鳴潮》PC 國際服、繁體中文、2560x1440 的使用者主動提供截圖。所有座標均為 `(x1, y1, x2, y2)`，右下界不包含在 ROI 內。禁止對整張截圖執行全文 OCR。

## 樣本檢查

九張來源 PNG 均為 2560x1440、32-bit ARGB。來源圖只存放於被 Git 忽略的 `samples_private/`；`debug_output/` 只允許保存下列小型 ROI、其前處理版本與 OCR JSON，不可複製完整原圖。

## 頁面分類

| ROI | 座標 | 用途 |
| --- | --- | --- |
| `page_header` | `(45, 35, 800, 190)` | 辨識 `聲骸`、`聲骸強化` 或選擇頁的 `COST` / `全部` 錨點 |
| `enhancement_state` | `(240, 240, 920, 330)` | `聲骸強化` 下分辨單一 `+N` 與素材預覽 `+0 > +15` |
| `material_grid` | `(1340, 55, 2490, 1145)` | 素材卡片網格的補充視覺證據；不執行全文 OCR |

分類順序：

1. 先驗證解析度；不符時回傳 `unknown`，不得猜測。
2. 只 OCR `page_header`。
3. `聲骸強化` 再 OCR `enhancement_state`；出現目前與預測等級的箭頭時分類為 `enhancement_material_selection`，否則為 `echo_enhancement`。
4. `COST` / `全部` / 套裝篩選錨點分類為 `echo_selection`。
5. 單獨 `聲骸` 錨點分類為 `character_echo_overview`。
6. 證據不足時回傳 `unknown`。

## 聲骸強化頁

強化資訊位於左側固定面板，副詞條列的垂直節距為 57 px。

| 等級 | `(268, 258, 410, 306)` |
| 經驗值文字 | `(680, 258, 895, 306)` |
| 經驗條（穩定偵測用） | `(268, 300, 895, 326)` |
| 第一主屬性 | `(260, 336, 900, 393)` |
| 固定主屬性 | `(260, 393, 900, 450)` |
| 副詞條 1 | `(285, 450, 895, 507)` |
| 副詞條 2 | `(285, 507, 895, 564)` |
| 副詞條 3 | `(285, 564, 895, 621)` |
| 副詞條 4 | `(285, 621, 895, 678)` |
| 副詞條 5 | `(285, 678, 895, 735)` |
| 完整資訊面板（單次偵測 OCR） | `(240, 150, 920, 750)` |

單列解析時，屬性名稱主要位於 `x=325..720`，數值位於 `x=740..895`。數字與百分比走獨立正規化及範圍驗證；屬性名稱以繁體中文詞彙表保守比對。只有正規化後為完整已知詞、前綴屬於已量測的 UI 圖示白名單，且同列數值具有高信心時，才校準圖示造成的名稱信心下降；模糊、歧義或弱數值證據不會被提高。

| 固定主屬性 | `(1995, 355, 2485, 412)` |
| 副詞條區 | `(2000, 405, 2485, 650)` |
| 聲骸清單（僅找選中卡與角色徽章） | `(275, 210, 810, 1300)` |
| 15 個可見卡片左上狀態區 | 每格 `58 x 58`，只涵蓋金框與角色徽章 |
| 選中卡中央卡面 | 每格內相對 `(45, 38, 142, 138)`，排除外框、角色徽章與底部文字 |
| 15 格可見清單脈絡 | 各格同一個中央 `97 x 100` 卡面，只產生 pHash，不做 OCR |
| 裝配角色文字 | `(1980, 1200, 2480, 1295)` |
| `卸下／裝配` 主要操作 | `(1980, 1280, 2240, 1390)` |
| 棄置切換圖示 | `(2305, 235, 2375, 302)` |
| 選中卡片紅色徽記 | `(755, 280, 795, 325)` |
| `已棄置` 提示 | `(950, 245, 1610, 335)` |
| 合併詳情 OCR | `(1900, 150, 2520, 700)` |

選擇頁詳情會解析最多五條副詞條。裝備狀態先以唯一金色選中框定位卡片，再交叉檢查卡片
左上角色肖像徽章、右下 `…裝配中` 與 `卸下／裝配`。只有一致證據才輸出 `true` 或
`false`；找不到唯一選中卡、徽章不完整或文字與圖示衝突時輸出 `null`。卡片亮暗與一般
邊緣不構成裝備證據。此狀態只表示「某角色已裝配」，不得由徽章猜測角色名稱或永久槽位。

裝備判斷已使用一張 Git 忽略的 2560x1440 私有正向樣本校準：樣本同時具有唯一金色選中
框、選中卡左上角色肖像、右下 `…裝配中` 與 `卸下`。原始樣本不會加入 repository，
校準結果也不會讓程式由肖像外觀推測角色身分。若只有金框、只有肖像，或右下文字互相
矛盾，仍維持 `null`。

Live 穩定判斷不再要求 15 個卡片角落同時穩定。那些角落與完整清單仍會交給解析器判斷
裝備狀態，但不會因其他卡片動畫而阻塞 OCR。穩定門只比較右側文字欄位、右下裝配文字，
並由完整清單在記憶體中導出「唯一選中格」與選中卡中央 pHash 兩個短期標記。切換選中格、
選中卡面或裝配文字仍會觸發新解析；任何卡片像素都不會寫入硬碟。

### 同一次 Capture 的回訪身分證據

遊戲畫面沒有可信的聲骸唯一 ID。為避免使用者依序查看 A、B、再回到 A 時重複建立紀錄，
選擇頁會在記憶體中裁切卡片中央區，立即轉成短期 pHash 證據後釋放像素。只有同時符合
下列條件才可接回本次 Capture 內既有的本機 Session：

1. 只有一個未進入素材消耗流程的候選 Session，且目前與候選都是聲骸選擇頁。
2. 唯一金框位於相同的 3 x 5 可見清單格；卡片中央 pHash Hamming distance 不超過 4。
3. 15 格可見清單的脈絡 pHash 逐格 distance 不超過 4，總 distance 不超過 24。
4. 名稱、合法等級、COST、兩條完整主屬性與該等級應有的全部副詞條名稱／數值／單位一致。

缺少 COST、主屬性、副詞條、唯一選中格，或視覺候選不唯一時，都不會合併；最多標記為
可能回訪並建立新的 Session。持久資料只包含格位、選中框 bbox 與 64-bit pHash 字串，不
包含卡片裁切或像素陣列。這些證據在 Capture 結束時失效，不可跨 Capture 重用，也不得
視為遊戲提供的唯一 ID。舊有歷史不做回填或自動合併。

棄置事件至少需要文字提示或圖示模板證據；本 POC 的第 7 張可由 `已棄置` 提示直接確認。未來若只剩持續性紅色圖示，需先補充圖示模板再提高信心。

| 已選舊聲骸卡片 | `(1350, 600, 1590, 890)` |

| `強化並調諧` CTA | `(270, 1260, 900, 1370)` |

素材預覽的 `EchoObservation.level` 保存目前等級，預測等級另存於 `projected_level`；主屬性同理，不可把預測值當成已完成結果。素材槽只提供「有一顆 +15 聲骸被選入」的證據，Session 身分仍由時間脈絡與畫面角色推導，絕不使用右下角特徵碼。

## 前處理與穩定判斷

- 保留原色 ROI 供 OCR detector 使用；另產生 2x 放大、灰階、CLAHE 與 Otsu/adaptive threshold 版本供低信心重試。
- pHash 僅計算頁面錨點、名稱／等級、主屬性、副詞條、棄置與素材槽等固定 ROI；排除星空背景、角色動畫、貨幣與右下角特徵碼。
- 即時模式需連續 2 至 3 個相近 ROI 才宣告穩定；靜態序列中的每個使用者提供檔案視為已穩定 snapshot。
- 一般穩定門的 pHash/SSIM 只決定是否重新解析，單獨不得產生或恢復 Echo Session ID；
  只有上述同次 Capture 的選擇頁證據，搭配唯一候選與完整結構化簽名，才可接回既有的
  本機 Session。
- semantic state key 不包含來源時間、檔名、OCR confidence、debug 路徑或特徵碼；相同穩定狀態不得重複發事件。
