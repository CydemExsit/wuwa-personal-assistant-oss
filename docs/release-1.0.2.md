# V1.0.2 辨識工作流程修正版

這個版本處理「已經辨識成功, 但不知道接下來要做什麼」以及重複辨識看起來混在一起的
實際使用問題。辨識與整理現在是兩件事: 結果會自動保存, 使用者可以直接在遊戲中切到
下一顆; 保留、淘汰及關聯角色位置都只是可選的本機整理動作。

## 已修正

- 每次按下開始辨識都建立清楚的「本次辨識」批次, 清空上一批留在 live 頁的結果與對照表。
- Live 頁只顯示「本次第 N 顆」, 不再暴露 `echo-session-0001` 之類內部識別碼。
- 歷史頁增加「辨識批次」欄, 每顆詳情只顯示可歸屬於該顆的 observation 與事件, 不再把
  同一 Capture 的所有事件塞進每一顆時間線。
- 辨識結果明確標示已自動保存; 新增直接的「保留這顆」「淘汰這顆」與「關聯到角色位置」
  操作。角色關聯必須明確選擇角色與位置 1-5, 不會暗自猜測。
- 結構化狀態完全相同時不再重複寫 observation 或重新評分; 有實際欄位變化但沒有事件時
  仍會保存, 不會把 `events=[]` 錯當成相同狀態。
- OCR 完成前畫面已切換時, tracker 採 prepare/commit 流程; 已分析完成的穩定素材頁仍按
  時序保存, 所以「來源聲骸 → 素材選擇 → 新聲骸」不會因 backpressure 合併成同一 Session。
- 聲骸選擇頁解析範圍擴充為最多五條副詞條, 避免 +20/+25 的第四、第五條遺失而使評分偏低。
- 修正舊聲骸的保留／淘汰 callback 晚於下一顆結果時覆蓋 live 頁的 race condition。
- runtime 錯誤會先安全停止 capture worker 並關閉本次資料庫紀錄, 之後可重新開始, 不會留下
  背景辨識工作阻擋下一次 Start。

## 裝備狀態的安全限制

聲骸選擇清單的角色肖像徽章確實是裝備狀態的正向線索, 但現有私有樣本沒有「被選中且
已裝備」的卡片。卡片本身的亮暗與邊緣不能當成徽章, 因此 V1.0.2 只保留三態欄位並顯示
「無法確認」, 不會把亮斑猜成已裝備或把暗色卡片猜成未裝備。取得一張已知槽位的正向
校準截圖後, 才能安全啟用自動徽章判斷; 即使判斷到徽章, 也不會猜角色身分或永久槽位。

## 資料相容性

本版沒有資料庫 migration。既有 observation、評分、角色關聯與歷史紀錄都保留; 新版只會
阻止之後產生語意重複資料, 不會自動刪除使用者先前已保存的紀錄。
