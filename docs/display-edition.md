# 雙模式獨立版 1.1.0

本專案以原版 1.0.35 (`f5fb549`) 為基底，提供可切換的單螢幕小面板及雙螢幕完整工作區。原版專案、執行檔及資料庫保留。兩個模式在此版本內共用角色、聲骸、歷史紀錄及評分設定。

## 啟動與設定

第一次啟動會顯示引導，選擇單／雙螢幕、遊戲顯示器及 1920x1080 或 2560x1440，再測試擷取。之後可在「設定 → 一般設定 → 被動擷取」調整；按儲存後生效。模式、螢幕或解析度變更會停止目前辨識，需要再次按啟動。

遊戲使用無邊框且填滿所選顯示器；選項表示實際畫面像素尺寸，必須與該螢幕一致。這個版本未宣稱支援其他比例、黑邊、非滿螢幕遊戲視窗或獨佔全螢幕。設定不會修改 Windows 或遊戲解析度。

## 單螢幕小面板

在「聲骸強化」選好角色／評分設定，按「啟動小面板」，再回遊戲的聲骸清單。面板顯示：

- 聲骸名稱與等級。
- 聲骸累積分、替換目標分數及評分依據。
- 保存與升級建議。
- 辨識中、上次結果、等待畫面、辨識不足等狀態。

替換目標沿用完整工具的角色聲骸位置選擇；未選目標時顯示 `—`，不把未知分數當成零。升級建議使用既有決策，保存建議摘要既有門檻與判定；「停止投入」不等於自動淘汰，也不排除對其他角色的用途。

辨識不足會列出待確認欄位並隱藏不可靠的分數／明確建議。回工具按「修正 OCR」補資料後，完整工作區與面板一起更新。換聲骸或評分尚未完成時，舊結果標為「上次結果」，新一筆分析完整完成後才恢復目前結果狀態。

面板啟動後一直顯示，不會因離開聲骸頁自動隱藏。離開清單時仍沿用現有辨識流程等待支援畫面；保留的結果明確標記為上次結果。回工具按「結束小面板」或關閉工具，結束面板及擷取。發生擷取錯誤時，面板保持可見並顯示狀態，讓使用者回工具處理。

## 位置及操作

設定提供左上、右上、左下、右下、左側中央和自訂位置。按住 Ctrl+Shift，再按滑鼠左鍵拖曳；放開修飾鍵後恢復點擊穿透。面板使用不啟用焦點的獨立視窗。沒有啟動／結束快捷鍵，也不會替遊戲按鍵。

拖曳位置以螢幕可用區域內的相對比例保存，重新啟動或換解析度時夾回可見範圍。顯示器移除或幾何改變會停止辨識並提示重新設定。

主工具會在啟動時配合螢幕可用空間調整視窗；高縮放下放不下的工作區可以捲動，設定與啟停控制仍可操作。

## 隔離與資料

- 執行檔：`WuwaDisplayAssistant.exe`，須與 `_internal` 放在同一資料夾。
- 預設資料根目錄：`%LOCALAPPDATA%\WuwaDisplayAssistant`。
- 原版根目錄 `%LOCALAPPDATA%\WuwaPersonalAssistant` 不會自動讀寫。
- 若要沿用原版資料，從原版匯出備份，在此版本的「本機資料與備份」預覽並匯入。兩個版本不共用即時資料庫。
- 螢幕畫面、OCR 與私人樣本保持本機；發布的程式碼與封裝不包含私人資料。

## 擷取與視窗邊界

完整顯示器畫面只短暫存在記憶體。1080p 會按比例對應每個允許的 ROI，僅將小範圍正規化至既有 parser 的參考座標；1440p 保留原路徑。完整畫面不另行縮放、排隊或寫檔。

Windows 10 2004+ 的 `WDA_EXCLUDEFROMCAPTURE` 用於本工具自己的小面板，並讀回確認。Qt 的輸出視窗旗標提供置頂、不啟用焦點及點擊穿透；修飾鍵狀態使用 Qt 查詢，不安裝鍵盤 hook。若擷取排除設定失敗，小面板模式拒絕開始辨識。

安全掃描只在 `ui/native_panel.py` 允許載入 user32 及兩個顯示親和性 API，只在 `ui/echo_panel.py` 允許點擊穿透旗標。其餘程式仍禁止遊戲視窗／程序尋找、注入、讀寫記憶體、渲染 hook、輸入模擬、封包操作與完整擷取畫面持久化。

參考：[Microsoft SetWindowDisplayAffinity](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity)、[Qt 視窗旗標](https://doc.qt.io/qt-6/qt.html#WindowType-enum)、[Qt 修飾鍵查詢](https://doc.qt.io/qt-6/qguiapplication.html#queryKeyboardModifiers)。
