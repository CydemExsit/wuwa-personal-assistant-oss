# v1.0.29 — 資料載入與交付可靠性

本次逐項改善資料載入、關閉流程與 Windows 成品驗證；保留評分、辨識信心、重複聲骸規則及夜色粉紫介面。資料結構不需遷移。

## 五項驗收條件

1. **歷史紀錄**：清單摘要批次查詢，不讀取完整觀測內容。完整檢視使用同一個唯讀快照，重複聲骸每次刷新只整理一次，保留超過 1,000 筆的所有紀錄與成員導覽。既有分頁服務保留。
2. **角色資料**：批次取得技能、裝備、武器與隊伍，讓角色頁與裝備／養成計算重用角色資料，避免逐角色反覆讀取。
3. **最新觀測**：由資料庫依原有時間、序號與 ID 順序選出聲骸最新觀測。重複聲骸的歷史歸屬證據仍完整參與判定，但不累積完整觀測物件。
4. **安全關閉**：畫面顯示關閉進度，事件迴圈持續回應；取消可省略的讀取，等待必要保存及擷取停止後才釋放資料庫。關閉錯誤必須保留可見訊息與重試途徑。
5. **Windows 成品驗證**：CI 通過品質檢查後執行既有封裝流程，檢查啟動、離線 OCR、來源模組、資源與非預期 DLL，保存依賴版本與驗證報告。

## 效能與行為證據

相同的人工暫存資料測量：10／50／100 位角色由 22／102／202 次查詢降為各 7 次；1,000 筆歷史紀錄由 2,001 次查詢降為 5 次。這是查詢次數比較，不是對實際使用等待時間的保證。超過單批上限時採用有界批次，避免 SQLite 參數數量限制。

新增測試涵蓋跨批次紀錄完整性、讀取期間新增資料的快照一致性、最新觀測的時間／序號／ID 排序與資料集隔離，以及不載入歷史完整觀測物件。原有重複聲骸、評分與歸屬測試持續保護既有規則。

關閉流程在 125%／200% 的真實 Qt 畫面驗證：350ms 慢速讀取期間事件迴圈持續回應，狀態文字完整可見，已提交保存完成後才關閉。回歸測試另覆蓋取消等待中的讀取、重複關閉、準備／工作失敗後重試及事件迴圈提前結束的清理。
