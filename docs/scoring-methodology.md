# 聲骸評分與強化決策方法

> v1.0.12 採官方調諧數值機率與實用品質基準；既有自訂設定保留其版本。
> 角色需求、使用率與來源詳見 [角色評分與來源](character-scoring-sources.md)；
> 角色總覽現在預設使用角色需求參考，不再預設以通用輸出型替所有角色排名。

## 1. 文件目的

本文件記錄 v1.0.12 聲骸評分與強化停止建議方法。核心原則是：

- 評分設定、Roll 值與機率假設必須資料驅動並有版本；
- 每個分數都能拆解，不能只顯示不透明的總分；
- OCR 或資料不足時回傳人工確認，不以模糊比對補出答案；
- 社群觀察值及均勻機率 fallback 不得標示為官方資料；
- 決策引擎提供可測試的 V1 建議，不宣稱是完整戰鬥模擬或最佳停止解。

實作位於 `src/wuwa_assistant/scoring/`，內建資料位於
`src/wuwa_assistant/data/scoring/`。評分層只處理結構化資料，不負責擷取畫面、
控制遊戲或執行 OCR。

## 2. 版本化資料與來源狀態

### 2.1 評分模板

`templates.v1.json` 的目前資料版本為 `scoring-templates-2026.09-v3`，包含四個可編輯的
起始模板：

| Template ID | 類型 | 初始設計重點 |
|---|---|---|
| `generic_dps_v1` | 通用輸出型 | 暴擊、暴擊傷害、攻擊百分比及角色主要傷害類型 |
| `healing_hp_v1` | 治療／生命型 | 生命百分比、固定生命及共鳴效率 |
| `defense_v1` | 防禦型 | 防禦百分比、固定防禦及共鳴效率 |
| `energy_requirement_v1` | 共鳴效率需求型 | 達到 ER 門檻前提高共鳴效率價值 |

模板的 provenance 狀態是 `project_default`，且 `is_official` 為 `false`。這些權重是
方便首次使用及建立角色設定檔的中性起點，不是官方角色配置，也不是網路 Tier List。
使用者可以依角色、武器、共鳴鏈、隊伍及實際輪轉建立或修改資料庫中的設定檔。

每個模板包含：

- 基礎 `StatWeight`；
- 依角色輸出方式啟用的 `ConditionalWeight`；
- 可選或必要的 `ThresholdRule`；
- 可選的 `CritBalanceRule`；
- 可調整的及格、完美與極品門檻；
- 所依賴的 Roll 資料版本。

`load_template_seed_definitions()` 提供穩定、JSON-safe 的 seed contract，讓資料層可以
依模板名稱及版本重複執行而不產生重複資料。條件權重會同時保留原始條件描述，並展開成
目前 SQLite schema 可保存的 condition-keyed 權重列。

V1.0.4 的資料版本為 `scoring-templates-2026.08-v2`。其中只有 `generic_dps_v1` 維持
穩定 ID 並升級到模板版本 2：門檻為 50／65／85／93，四種傷害加成的通用基礎權重為
0.55，角色輸出條件倍率為 1.50。其他三個系統模板仍是版本 1。seed 只會以較新版本更新
相同種類的系統模板；使用者複製或建立的設定檔及既有決策不會被覆寫。

### 2.2 Roll 值及機率

新預設使用 `rolls.v2.json`、版本 `echo-rolls-2026.09-official-v2`。
來源為[庫洛官方韓文調諧公示](https://sdk-global.kurogames.com/pro/agreement/common/language_ko/product_info)，
其[公開PDF](https://sdk-prod-cdn-aws.kurogame-service.com/pro/agreement/common/language_ko/product_info.pdf)第3–10頁，查核2026-09-23。
檔案記錄來源網址與SHA256；對照原表的每一檔數值，不以等機率代替。

- 13種副詞條等機率，調諧不重複：開出k條後，每個剩餘種類機率為1/(13-k)。
- 數值機率不均等。例如暴擊6.3/6.9/7.5%各約23.3333%，9.9/10.5%各3%；固定攻擊40機率52.4272%。
- 公示百分率四捨五入至4位小數，程式只正規化微小合計誤差。
- 只處理普通調諧，未加入定向重構/鎖定功能。連續調諧按公示條件分布推算。
- 數值與機率是官方資料；角色權重、Roll credit、P99參考、分數門檻與強化建議是專案方法。

`rolls.v1.json` 的 `echo-rolls-2026.08-v1` 仍保留：舊自訂設定及歷史決策使用原本均勻Roll假設、
理論最高五項權重分母。系統模板升版不覆寫自訂設定、已保存決策或掃描資料。
未知版本仍拒絕計分。新自訂設定可複製目前模板；舊設定不被暗中轉換。

## 3. 輸入驗證與詞條正規化

### 3.1 精確詞條識別

評分引擎只接受已知的繁體中文詞條名稱、單位及數值組合。名稱採精確映射，不在評分層
執行模糊比對。例如：

- `攻擊` 加 `%` 映射為 `attack_pct`；
- `攻擊` 無單位映射為 `flat_attack`；
- `攻擊百分比` 加 `%` 也可作為明確別名；
- 暴擊、暴擊傷害、普攻、重擊、共鳴技能及共鳴解放傷害加成都使用不同 key。

未知名稱、錯誤單位或不完整欄位不會被推測成最相近詞條。結果會列入
`unknown_stats`，總分為 `null`，並設定 `requires_manual_confirmation`。

### 3.2 Confidence 及 Roll 驗證

`EchoScoringEngine` 的預設最低 confidence 是 `0.85`。名稱、數值或 OCR 組合低於門檻
時會列入 `low_confidence_stats`，不產生可採信分數。使用者完成人工修正後，應由應用層
以已確認狀態重新建立輸入並重新評分，同時保留原值及修正 audit log。

數值還必須落在目前 Roll 資料版本的已知集合內。只允許小幅數值表示誤差：小數 Roll
容差為 `0.051`，整數 Roll 容差為 `0.51`。超出容差的值列入 `invalid_rolls`，不會被
夾到最近的高 Roll 或低 Roll。這個行為可避免新版本數值或 OCR 錯字被誤當成既有資料。

## 4. 0–100 分數與 breakdown

### 4.1 Roll 正規化

對已確認詞條值 `x`，使用該詞條目前版本的最小值 `min` 及最大值 `max`：

```text
roll_ratio = clamp((x - min) / (max - min), 0, 1)
roll_credit = 0.55 + 0.45 * roll_ratio
```

`roll_ratio` 再依版本化門檻分類為低、中、高及頂 Roll。最低 Roll 仍保留 `0.55` 的
credit，因為它確實提供角色可用屬性；高 Roll 則逐步接近 `1.0`。Roll tier 是說明資訊，
實際加分使用連續的 `roll_credit`，避免同一 tier 內所有值被壓成完全相同。

### 4.2 單條詞條貢獻

每條已確認詞條的加權點數為：

```text
weighted_points =
    base_weight
    * roll_credit
    * conditional_multiplier
    * threshold_multiplier
    * crit_balance_multiplier
```

breakdown 會保存原值、Roll ratio、Roll tier、基礎權重、各倍率、最終加權點數、
confidence 及簡短說明。條件倍率只有在 `ScoringContext.conditions` 的 key 和預期值完全
相符時才啟用。例如角色確實以共鳴技能為主要輸出時，才提高共鳴技能傷害加成的權重。

### 4.3 總分

v1.0.11 先以目前角色權重/條件計算隨機五條已調諧副詞條的加權點數分布。
13種類等機率且不重複，數值採官方分布。以P99品質對應90分，理論最佳五條頂值對應100分：

```text
E = 已開詞條加權點數總和
R = 隨機五詞條加權品質的第99百分位
I = 同一角色/條件的理論最佳五詞條加權點數
E <= R: score = 90 * E / R
E > R:  score = 90 + 10 * (E-R)/(I-R)
最終限制 0..100；R與I相同的退化分布改用線性0..100。
```

這是一個專案選擇的實用參考，**分數本身不是百分位，也不是官方傷害公式**。
讓常見有效數值獲得合理分數，同時保留高品質裝備的提升空間，避免優秀裝備全擠在100分。
未升滿只計入已開詞條；剩餘潛力另外呈現。跨角色分數是相對各自需求，不代表相同戰力。

參考分布使用有界動態規劃，每種詞條選或不選，取五條係數；數值點數量化為理論上限的
1/10000，每條四捨五入後，總量化誤差不超過理論上限0.025%。快取最多256個角色/條件組合。
剩餘預測仍逐值枚舉並使用同一分數尺度；同分結果合併機率可減少無用運算。

舊版自訂設定保持 `100 * E / 最高五項基礎權重總和`，上限100。

預設顯示區間為：

| 分數 | 預設分類 |
|---:|---|
| 0–54 | 淘汰或過渡 |
| 55–69 | 可用但仍是弱點 |
| 70–87 | 及格 |
| 88–94 | 完美 |
| 95–100 | 極品 |

實際分類使用設定檔中的 `ScoreThresholds`，不是寫死在 UI 的常數。使用者修改門檻後，
之後的新評分會使用新門檻；既有持久決策仍保留當時的設定檔版本，只有使用者明確要求時
才重新試算。

從 V1.0.4 起保留兩個不同分母的分數；v1.0.11 主要顯示副詞條累積分，舊的已開詞條品質移至提示，避免混淆：

```text
opened_slot_quality =
    100 * sum(weighted_points) / top_N_base_weights

full_piece_accumulated =
    上述版本對應的 score(E, R, I)
```

`N` 是目前已確認且可計分的副詞條數。前者回答「目前已開的詞條品質如何」，後者回答
「相對該版本完整五詞條的品質基準，現在累積了多少」。因此 +10 的累積分偏低並不等於
兩條 Roll 都很差。剩餘詞條枚舉另提供預估完成期望值與範圍，三者不可互相冒充。

評分 breakdown 的每條畫面貢獻按 `單條加權點數 / 全部加權點數 * 實際分數` 分攤，
讓各列貢獻相加對應副詞條累積分。高分段也使用同一方式。原始 `weighted_points` 仍保留在結構化 audit。

## 5. 暴擊平衡規則

一般輸出模板以以下參考比例判斷目前面板偏向哪一側：

```text
crit_balance_ratio = (panel_crit_damage - 100) / panel_crit_rate
target = 2.0
```

也就是暴擊率與「面板暴擊傷害減 100」約為 `1:2`。比例高於目標及 tolerance 時，
提高暴擊率詞條倍率並降低暴擊傷害倍率；比例低於目標時反向處理。調整幅度受到
`max_adjustment` 限制，避免平衡修正壓過角色本身的詞條權重。

面板資料可能因武器、戰鬥 Buff、共鳴鏈或隊伍效果而改變，因此 `ScoringContext` 必須由
使用者設定或可信的本機資料提供。一般模板缺少面板資料時會保留未修正分數並顯示說明；
若某角色設定檔將此 context 標為必要，則決策改為人工確認。

V1 不模擬戰鬥中的動態 Buff 時序。使用者若希望把特定 Buff 納入平衡，應直接提供對應
情境下的面板值或建立另一個角色設定檔。

## 6. 共鳴效率門檻

`ThresholdRule` 用來表達「達標前很重要，達標後邊際價值下降」的非線性權重。
`energy_requirement_v1` 的示範門檻為總共鳴效率 130，僅作為可編輯起點：

- 尚未達標時，ER 詞條倍率為 `1.20`；
- 達標後，倍率回落為 `0.75`；
- `current_totals[energy_regen]` 是加入目前聲骸詞條前的角色總值；
- 此模板將該 context 設為必要，缺少時會要求人工確認。

門檻值不代表所有角色的通用答案。每個角色應依輪轉、隊伍供能、武器及實際需求覆寫。
超過門檻後仍可能有價值，因此 V1 使用降低倍率而不是直接歸零。

## 7. 剩餘詞條枚舉

在 +5 至 +24 各等級（每五級開啟一格），`enumerate_remaining()` 依目前已出現詞條與五個
總欄位建立剩餘結果分布。流程如下：

1. 先驗證現有詞條、confidence、Roll 及必要 context；
2. 排除已出現詞條，避免同顆聲骸出現重複副詞條；
3. 枚舉等機率、不重複的剩餘詞條組合；
4. 逐一使用版本化資料中的每個 Roll 值，不以 tier 平均值取代非線性門檻計算；
5. 每個 Roll 值使用對應版本機率，新預設使用官方公示；
6. 對每個 path 以 streaming accumulator 計算分數與門檻機率，不保留龐大的完整結果清單。

輸出包含：

- 最低、最高及期望最終分數；
- 達到可用、及格、完美及極品門檻的機率；
- 枚舉 path 數量及總機率；
- 使用的 assumptions version 及來源說明。

Roll tier 只用於說明高低，不會取代逐值枚舉，也不會把未知 OCR 值塞入既有 tier。
權重為零的合法詞條仍保留在候選中，因為「對角色沒有價值」不代表「不可能出現」。
現有詞條只要有未知、低信心、未列 Roll 或必要 context 缺失，整個預測就回傳人工確認。官方提供調諧種類與數值機率，工具據此推算品質；品質達標機率仍依賴角色權重與情境，不是官方戰鬥收益。

## 8. 強化決策規則

`UpgradeDecisionEngine` 在 +5 至 +24 產生建議，+25 則標示已滿級。輸入包含：

- 目前 score breakdown；
- 剩餘詞條 projection；
- 角色設定檔及可調分數門檻；
- 現有同位置裝備分數及替換 margin；
- 角色是否已有及格裝備；
- 是否採 breadth-first progression；
- 同類胚子供給是 scarce、normal 或 abundant；
- 可選的同類候選數量。

可能輸出為：

| Action | 意義 |
|---|---|
| `continue` | 替換機率與預期提升符合投入門檻，或建議先觀察至 +15；無替換目標的後期才用通用門檻 |
| `stop` | 替換機率或預期提升相對成本過低；無替換目標的後期使用通用門檻 |
| `qualified_finish` | 目前已及格，可升滿並保留 |
| `cannot_surpass_existing` | 模型上限仍低於現有裝備及替換 margin |
| `max_level` | 已達 +25，沒有下一個強化節點 |
| `manual_confirmation` | OCR、Roll、context、等級或預測資料不足 |

breadth-first 模式會在角色尚未有及格聲骸時降低「繼續」所需機率，優先補齊帳號弱點；
已有及格裝備、胚子充足或同類候選很多時則提高要求。這些 V1 門檻是可測試的規則型
heuristic，不是 Dynamic Programming 或完整 Optimal Stopping。每個結果都保存 reason、
reason codes、分數範圍、機率及 assumptions version，方便日後比較與遷移。

V1.0.4 起，所需機率與各種情境調整由版本化的 `decision-policy.v2.json` 載入；v1.0.12 使用 `decision-policy.v3.json` 加入增量成本與替換機率。資料標示為
非官方 `project_default`，載入時會驗證支援等級、機率範圍、上下限與調整欄位。新決策的
`assumptions_version` 同時記錄 Roll 資料版本及決策政策版本；缺檔或格式錯誤時直接失敗，
不會無聲改用另一組硬編碼門檻。

每筆持久化決策另保存 profile version、observation payload version、DecisionInputs、
ScoringContext 與 deterministic evaluation fingerprint。寫入前會在同一 transaction 重新
驗證 Dataset、Capture Session、Echo Session、observation、Echo 與 profile 的關聯鏈；舊畫面
或跨 Dataset payload 不得改寫分數。只有最新 observation 的已確認分數會更新 Echo 摘要，
人工確認結果不會把先前已確認分數清成 `null`。

## 9. 已知限制與後續校準

V1 評分目前有以下限制：

- 只評副詞條；套裝、COST、主詞條是否正確由角色養成與 breadth-first 規劃層處理；
- 不執行完整傷害模擬，也不推導角色最佳隊伍或網路 Tier；
- 舊自訂設定保留其歷史資料版本，與新基準不可混比；
- 官方資料僅涵蓋公示機率，不驗證本工具的角色權重和停止策略；
- conditional 及 threshold context 依使用者設定，不從遊戲記憶體或帳號 API 取得；
- 新詞條、新 UI 名稱及新 Roll 值在資料更新前一律要求人工確認；
- 現有裝備分數只能比較使用相同設定檔及資料版本的結果。

後續校準應優先蒐集本機結構化強化紀錄，記錄資料版本、樣本數及觀察時間。任何社群資料
匯入都需人工啟用、離線驗證並保留 provenance，不得在背景無聲抓取網站。

## 10. 安全與隱私邊界

評分與決策模組是純本機 domain code：

- 不擷取桌面或遊戲畫面；
- 不讀取遊戲程序、記憶體、Handle、封包、log 或遊戲檔案；
- 不控制或模擬滑鼠、鍵盤、手把；
- 不注入、不掛接繪圖、不建立遊戲 Overlay；
- 不使用網路或雲端 OCR；
- 不保存完整 frame 或影片；
- 不執行強化、鎖定、棄置、選擇或其他遊戲操作。

它只接收 OCR／人工修正後的結構化詞條以及使用者設定，輸出 JSON-safe 的 breakdown、
projection 與 decision。畫面擷取的完整 frame 生命週期及 ROI-only 邊界仍由被動 capture
模組負責；評分層沒有也不需要任何 frame API。

## 11. v1.0.12 替換機率與成本

有現有裝備時，枚舉嚴格超越 `existing_gear_score + replacement_margin` 的機率及期望正向差額；等分不算提升。新建議不會以通用及格機率替代替換成功率，也不因上限稍高就建議繼續。下一節點只計未來成本，保留實際中間等級；成本越高，要求的成功率越高。5星成本表、逐級限制、版本化政策及來源見 [v1.0.12](release-1.0.12.md)。已有持久化決策保留原版本，重新試算採新政策。

## 12. v1.0.14 前期探索與目標差距

v1.0.14 使用 `decision-policy.v4.json`，以目標相對改善為主；v1.0.19 的 v5 政策另加入下節的弱目標品質檢查，v1.0.33 的現行 v6 再加入高品質近分候選的放寬規則。枚舉提供 `P(最終分 > 目標)` 與 `E[max(最終分 - 目標, 0)]`；後者表示保留現有裝備、只採用更好結果時的平均可得提升，並非傷害百分比。角色是否已及格及 breadth-first 設定不影響有目標時的投入要求；v6 僅在下述雙方目前均及格且接近時調降要求。

未滿三條已確認副詞條時，政策考慮到 +15 的探索成本。無目標時先觀察至 +15；有目標時仍排除上限無法超越、機率太低或成本對應提升太小的胚子。+15 後逐節點重新評估，+20→25 的高成本會提高繼續門檻。+0～4 尚未調諧且套裝、COST、主詞條方向相容時，可先到 +15；不預估未開詞條的完成分數或機率，滿分目標例外。已解鎖卻缺漏的詞條一律待確認，不當成未來潛力。

基準供給下，前期機率門檻為 `2% + 3% × 尚需EXP / 63500`；後期為節點基準加 `12% × 尚需EXP / 63500`。供給可再調整。所需平均提升為 `max(0.1, 0.75 × 尚需EXP / 63500 × 供給因子)`。只計未來節點投入，不重複計入已花材料。0→15 為39,600 EXP，+5→15 為35,200，+10→15 為23,100；+20→25 為63,500。+15 探索的建議仍以完整五詞條的可能改善篩選潛力，不代表三詞條必定能替換，也不是建議直接升滿。

這是明示版本、可檢驗的工具策略，不是官方最優停止解。既有角色權重、得分公式與歷史決策均保留；完整理由、材料及機率假設可在強化頁展開。替換套裝/COST不相容、資料缺漏時，不顯示誤導性的目標成功率或分差。

## 13. v1.0.19 弱目標的品質檢查

此規則由 `decision-policy.v5.json` 引入，現行 v6 保留。從 +15 開始，若現有目標與候選累積分都低於角色設定檔的「可用」門檻（預設55分），除了超越現有的機率和平均可得提升，還需要檢查升滿達到可用分的機率。品質機率使用同一個依未來節點成本、胚子供給調整的投入門檻；即使候選目前已超過很差的目標，也不能跳過此檢查。

若模型上限仍不到可用分，停止追加材料；若品質機率缺失或無效，顯示資料待補，不把缺資料誤判成低品質。這項檢查不要求完成期望分必須達55，也不要求達到及格或完美；有足夠上升機會的胚子仍可繼續。+15前保留既有探索規則，已達可用的候選、原本足夠好的替換目標沿用相對改善判斷。+25已無後續投入，仍直接比較替換收益。

回歸案例：洛瑟菈現有25.04分，+22候選為生命510、共鳴技能傷害9.4%、防禦60、普攻傷害7.1%。候選累積14.93、完成期望23.84、上限55.69；超越現有機率33.33%，但達可用55分只有0.67%，低於本節點約30.8%的機率門檻，故建議停止追加材料。這是工具的品質與成本篩選策略，沒有改動角色權重、得分公式或歷史紀錄。

## 14. v1.0.33 現有聲骸強化與高品質替換

比較前以已保存的聲骸 ID 核對目前聲骸與所選位置。相同 ID 改為「現有聲骸強化」，不以自身分數作為替換基準，也不顯示超越機率或分差。名稱、詞條、分數相同都不能取代 ID 核對；缺少 ID 時不推定為同一顆。保存到目標位置後即重新評估，切換目標時重新判定身分。

同一顆符合套裝、主屬性及位置 COST，且資料完整、目前累積分達角色及格門檻時，明確建議「升至 +25 並保留」，列出剩餘升滿成本；未達門檻仍按自身潛力判斷。已滿級顯示滿級狀態，配裝不符或資料待補優先提示，不因同一 ID 跳過檢查。

不同顆使用 `decision-policy.v6.json`：兩顆**目前累積分**都達該角色評分設定檔的及格門檻，且 `0 ≤ 現有分 − 候選分 ≤ 10`，將依實際剩餘成本與供給調整後的超越機率門檻、平均正向提升門檻各乘以 0.5。使用角色實際門檻（角色預設通常為70，通用輸出模板為65），不以預期完成分或已開詞條品質代替累積分。候選已超過目標、差距超過10分或任一方未及格，沿用一般規則。

例如 +20、一般供給、目標85分、候選75分，原機率要求35%與平均提升0.75分，改為17.5%與0.375分；兩者仍須同時通過，通過後才建議下一節點。候選74.99分則不適用。這是投入策略放寬，**不會提高顯示的實際超越機率**，也不保證升滿一定能替換。上限無法超越、資料不確定、配裝不符等限制保留；歷史決策與角色評分權重不改寫。

## 15. v1.0.34 分數顏色

聲骸的百分制分數使用同一條連續色帶，低分紅橘，依序經黃、黃綠、綠、青藍到高分紫色。五件500分總分以總分除以5換算；均分直接對應色帶，未齊全的總分維持待評分灰色。零分是已知低分，與未知資料分開。顏色依數值，及格與配裝適配仍由文字表達，不以顏色改寫或推定評分結論。

即時累積分、完成期望分、預估範圍端點及現有目標分各自採用此色帶；預估值仍為模型估計。副詞條貢獻、正負分差、機率使用各自原有表示方式。分數更新、角色切換及清除後會同步重設顏色。色帶與評分計算分離，所有配裝與歷史頁共享，沒有修改得分、權重、門檻或資料庫。
