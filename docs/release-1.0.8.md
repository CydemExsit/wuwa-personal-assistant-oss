# V1.0.8 — 從掃描結果決定聲骸養成順序

角色頁預設開啟「聲骸總覽」，用同一個可選評分基準比較已裝備副詞條累積分。
完整五件顯示均分 /100 與總分 /500；缺件或辨識不完整只顯示已評件數與部分均分，
排在完整配裝後，不把未知當零分。切換基準不寫入歷史評分，也不覆蓋角色原有設定。

「低分單件」可直接找出目前裝備最低分的 12 件，查看所屬角色、位置、等級與套裝，
按查看進入該角色的裝備區。「角色總分」則提供角色頭像、五個位置分數及養成摘要。
可依角色等級、武器、技能、聲骸未完成或聲骸資料待補齊篩選；原有編輯功能保留於
「角色養成」。八名已掃描角色使用附帶來源記錄的官方頭像，其他名字有本機文字頭像。

歷史紀錄預設折疊疑似重複掃描，顯示掃描次數。分組要求完整且完全相同的名稱、等級、
COST、主副詞條數值；不同已知套裝、不同手動裝備位置及已消耗紀錄不混在一起。
未知套裝僅在有唯一相符已知套裝時加入該組。分組在分頁之前進行，且可取消勾選看原始
掃描。所有原始聲骸、辨識觀察、人工修正、強化與消耗事件均保留；分組不等同遊戲內 ID。

穗穗位置 2、緋雪位置 5 尚未登記。愛彌斯有兩件最新辨識資料不完整／需確認，保留為
待評分並提示原因，不使用舊分數或猜測補滿。角色等級、武器與技能仍以本機已登記資料為準，
僅掃描聲骸不會讀入這些養成資料。

確認舊的空白「秧秧・玄翎」沒有裝備、武器、隊伍或人工養成變更後，已先以 SQLite
一致性備份演練，再封存該筆，保留有五件裝備的「秧秧·玄翎」。封存可還原，原始聲骸不變。

## 驗證與使用

完整品質檢查：758 項通過、1 項需連線的測試依設定略過；Ruff、格式、mypy、相依套件、
安全掃描與 diff 檢查通過。Windows 打包後的 OCR／啟動測試、八張頭像雜湊與 131 個
程式模組對照原始碼均通過。執行證據記於 `.codex/WORK_PROGRESS.md`。
回歸涵蓋缺分不算零、真正零分排序、套裝／手動位置衝突不折疊、切換基準、角色／單件
導航、保留編輯草稿、九張原始私有 OCR 樣本及兩張提供的裝備截圖。
封裝包含頭像，維持離線 OCR、PATH 隔離與 QtCore 啟動檢查。
